# 状态层 v2：键归一（第一步）

## 问题

状态以「主体·属性」为键。抽取时没有给出任何已有键，模型每次自己起名：同一件
事被写成 `叶楠·生日` 和 `叶楠·日历日期`，被写成 `合租房客厅地板·颜色` 和
`客厅地板·颜色`。两条事实因此落在两个键上，永远「对不上」，状态也就只能是单值。

## 做法

1. `biocore_memory/event/keynorm.py`
   - `extract_facts(events, llm, known_keys=None, *, batch=8, stats=None)`：每批把当前
     键表写进提示词，模型回来的事实先归到已有键上，固定输出
     `{subject, attr, value, turn, ts}`。
   - 提示词：`【已有键｜优先复用】` 按出现频次排序、最多 60 条（`KNOWN_KEYS_LIMIT`），
     要求「能选到就照抄，一个字都不要改；确实没有才新建」。
   - 机械归并只有两种：完全同名；同一属性下主体是多带限定的写法（`客厅地板` ⊂
     `合租房客厅地板`）。语义别名不猜，交给模型照抄键表。
   - `merge_fact_state`：同一键多值交给 `rolling.merge_state`，按 conflict 并存，
     每个值的轮次留在 `item["values"]`，`value` 拼成 `值1 / 值2`。
   - `state_line / state_lines_for / prepend_state_lines`：只渲染。命中事件涉及多值键时，
     块顶写一行 `【状态】主体·属性：值1（第a轮） / 值2（第b轮），未确定（n 种说法并存）`；
     单值键写 `，已确定`。注入点在调用方，未改 `events.py`。
2. `scripts/keynorm_report.py`：P01 的前后对比 + 两个目标键的完整状态。

## P01（388 轮历史，200 条抽取事实）

| 口径 | key 数 | 多值 key | 多值比例 |
| --- | --- | --- | --- |
| 归一前（cache 里的原始键） | 171 | 13 | 7.6% |
| 归一后（带键表回放 + 机械归并） | 169 | 15 | 8.9% |

key 数只少了 2 个，因为失败案例本来就是少数几对；变的是这两对从「两个单值键」
变成「一个双值键」，多值 key 因此从 13 涨到 15，比例 7.6% → 8.9%。

### 叶楠生日

```
归一前 叶楠·生日     = 八月十六号（用户曾误说）      （第165轮）
归一前 叶楠·日历日期 = 八月十八号                    （第183轮）
归一后 【状态】叶楠·生日：八月十六号（用户曾误说）（第165轮） / 八月十八号（第183轮），未确定（2 种说法并存）
        status=conflict  coexist=[八月十六号（用户曾误说）, 八月十八号]  superseded_by=None
```

### 地板颜色

```
归一前 合租房客厅地板·颜色 = 浅灰色                  （第279轮）
归一前 客厅地板·颜色       = 米色                    （第317轮）
归一后 【状态】合租房客厅地板·颜色：浅灰色（第279轮） / 米色（第317轮），未确定（2 种说法并存）
        status=conflict  coexist=[浅灰色, 米色]  superseded_by=None
```

## 这是怎么算出来的（没有跑模型）

输入是仓库里现成的 `cache/facts-P01.json`（旧提示词抽出的 200 条事实），不是新一次
模型作答。回放时把它按轮次还原成事件，再过一遍新的抽取/合并流程。

`叶楠·日历日期 → 叶楠·生日` 这一步机器判断不了，脚本里以 `REPLAY_ALIASES` 显式写出，
含义是「模型看到键表后会做的照抄决定」。`合租房客厅地板·颜色` 那一对不需要别名，
由 `normalize_key` 的限定词规则归并。所以：**回放证明的是管线（键表进提示词 → 复用 →
同键多值合并 → 状态行），不是模型的服从率**；服从率要在一次真模型抽取上量。
